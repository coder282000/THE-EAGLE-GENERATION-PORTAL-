## 1. Voice and tone

The Eagle Generation Portal speaks as a **Kingdom-driven leadership community**, not as a generic SaaS tool.

| We are | We are not |
|--------|-----------|
| Warm, direct, encouraging | Corporate, bureaucratic, distant |
| Clear and specific | Vague, abstract, hedging |
| Respectful of the user's time | Chatty, self-congratulatory |
| Action-oriented | Passive, "it may be possible to..." |

### 1.1 The three pillars are the taxonomy

Always refer to the programmes as **Marketplace**, **Governance**, **Technology**. Never "Business / Tech / Leadership" or generic categories. This is a Charter §3.1 rule and it propagates into every piece of copy.

### 1.2 Length

- Button labels: 1–3 words
- Field labels: 1–4 words
- Hints: one short sentence, max 12 words
- Empty state body: one sentence, max 20 words
- Error messages: one sentence, specific cause, specific fix

### 1.3 Voice by state

| State | Tone |
|-------|------|
| Welcome | Warm, brief — "Welcome aboard. Let's get you started." |
| Instruction | Direct imperative — "Select your chapter." |
| Confirmation | Calm, factual — "Application submitted." |
| Warning | Serious but not alarmist — "This cannot be undone." |
| Error | Neutral, blameless, actionable — "That email is already registered. Sign in instead?" |
| Empty | Encouraging — "No applications yet. New ones appear here as they arrive." |

## 2. Copy patterns by context

### 2.1 Buttons

| Do | Don't |
|----|-------|
| "Save" | "Save changes to your profile" |
| "Approve" | "Yes, approve this" |
| "Continue" | "Proceed to next step" |
| "Cancel" | "No thanks, go back" |
| "Delete" (destructive) | "Remove permanently" |

Verb-first, no pronouns. Never "Click here".

### 2.2 Field labels and hints

- Labels: title case for single words, sentence case for phrases
- Hints below label, in `text-fg-subtle`
- Never place essential information in a placeholder — it disappears on typing

**Good:**


Email address
We will send your application confirmation here
victorkirimi01@gmail.com

### 2.3 Empty states

Structure: **Title + one-sentence body + optional action**

| Context | Copy |
|---------|------|
| No applications match filters | "No applications match your filters." + "Clear filters" button |
| No applications at all | "No applications yet. New ones will appear here as they arrive." |
| No events | "No events scheduled right now. Check back soon." |
| No notifications | "You are all caught up." |
| No results in search | "Nothing matched '{query}'. Try a different search term." |
| Permission denied | "You do not have access to this page. Contact your chapter leader if you believe this is a mistake." |
| Offline | "You are offline. Changes will sync when you reconnect." |

### 2.4 Error messages

Structure: **What happened + what to do about it**.

| Situation | Copy |
|-----------|------|
| Required field empty | "Please enter your email address." |
| Email format wrong | "That email address does not look right." |
| Email already registered | "That email is already registered. Sign in instead?" |
| Password too short | "Passwords must be at least 8 characters." |
| Server error | "Something went wrong on our side. Try again in a moment." |
| Network error | "We could not reach the server. Check your connection." |
| Permission denied | "You do not have permission to do that." |
| File too large | "That file is too large. Maximum size is 5 MB." |
| Unsupported file type | "That file type is not supported. Try PDF, JPG, or PNG." |

**Never:**
- "An error occurred." (no recovery path)
- "Invalid input." (no field specified)
- "Error 500." (user cannot act on a code)
- Blame the user ("You entered the wrong password")

### 2.5 Confirmation dialogs

| Situation | Title | Description | Confirm label |
|-----------|-------|-------------|---------------|
| Approve application | "Approve {name}?" | "A member number will be issued and a welcome email sent." | "Approve" |
| Reject application | "Reject {name}?" | "The applicant will be notified without reason. This cannot be undone." | "Reject" |
| Bulk approve | "Approve {n} applications?" | "Each applicant will receive a welcome email." | "Approve {n}" |
| Bulk reject | "Reject {n} applications?" | "Each applicant will be notified. This cannot be undone." | "Reject {n}" |
| Delete account | "Delete your account?" | "Your profile and activity will be removed. Financial records are retained as required by law." | "Delete account" |

Use the correct plural form. Never "1 application(s)".

### 2.6 Success confirmations (toast)

| Action | Toast |
|--------|-------|
| Application approved | "Approved. Welcome email sent to {email}." |
| Application rejected | "Rejected. Notification sent." |
| Application scheduled | "Interview scheduled for {date}." |
| Note added | "Note added." |
| Export started | "Export will download in a moment." |
| Settings saved | "Settings saved." |
| Password changed | "Password updated." |

Short. Past tense. No exclamation marks.

### 2.7 Loading states

Prefer skeleton placeholders over spinners. When a spinner is unavoidable, pair with text:

- "Loading applications..."
- "Saving..."
- "Approving..."
- "Searching..."

Never "Please wait" alone.

### 2.8 Notifications

- New announcement: "{author} posted: {title}"
- New message: "{sender}: {first 60 chars}"
- Approval granted: "Your membership was approved."
- Interview scheduled: "Interview scheduled for {date} at {time}."
- Payment received: "Payment of {amount} received."

Never use urgency markers ("URGENT", "!!!") in automated copy.

## 3. Naming conventions

### 3.1 Feature names

| Feature | Call it | Not |
|---------|---------|-----|
| Membership application | "application" | "request", "submission" |
| The applicant before admission | "applicant" | "user", "person" |
| The person after admission | "member" | "user" |
| Group of members in a city/campus | "chapter" | "group", "hub" |
| Dated intake of a course | "cohort" | "class", "batch" |
| Course stage | "phase" | "level", "stage" |
| Programme category | "pillar" | "category", "topic" |
| Guide/teacher | "mentor" | "coach", "tutor" |
| Person being guided | "mentee" | "student" (unless enrolled in a course) |
| Money transfers between members | "transfer" | "send money" |
| Physical event ticket | "ticket" | "pass", "entry" |

### 3.2 British English

- "organisation" not "organization"
- "colour" not "color"
- "licence" (noun) / "license" (verb)
- Dates: `d MMM yyyy` — "10 Sep 2026"
- Times: 24-hour in admin, 12-hour with am/pm in member-facing
- Currency: "KES 1,500.00" — currency code first, thousands separator, two decimals

### 3.3 Numbers

- Money: "KES 15,000.00" (not "Ksh 15,000" or "15,000 KES")
- Percentages: "65%" (no space)
- Large numbers: "1,247" — thousands separators always
- Ranges: "10–500" (en-dash, no spaces) or "10 to 500" in body text

## 4. Notification channels

| Channel | Tone | Length |
|---------|------|--------|
| In-app toast | Short, factual | <=8 words |
| Push notification | One sentence | <=15 words |
| SMS | Minimal, no greeting | <=160 chars total |
| Email subject | Action-oriented | <=50 chars |
| Email body | Full context, one CTA | Any |

Persona P1 (Grace) has intermittent data — **prefer SMS and push over email** for time-sensitive notifications (Charter §16, persona P1).

## 5. Localisation notes

- All user-facing strings live in `messages/en.json` (or equivalent i18n store), **not** hardcoded in components
- Never concatenate strings — use full sentences with placeholders
- Never assume word order — use ICU message format for plurals and gender
- RTL support: use logical CSS properties (`ps-*`, `pe-*`) not `pl-*`, `pr-*`

Launch languages (pending Charter Appendix B Q-11):
- English (v1)
- Kiswahili (R2)
- French (R2, DRC)

## 6. Approved terminology

Terms from Charter §30 glossary that must not be paraphrased:

- The Eagle Generation (never "TEG" in member-facing copy; admin may use TEG internally)
- Marketplace / Governance / Technology (capitalised as pillars)
- Chapter, Cohort, Phase, Pillar, Tier
- Student / Professional / Associate (tiers)
- KYC, AML, CDD, PEP, SAR — spelled out on first use, acronym thereafter
- M-Pesa (never "Mpesa" or "MPESA")

## 7. Copy review process

Before a string ships:

1. Author drafts in Figma or in code
2. Product Lead reviews against this guide
3. If user-facing and touching a new journey, test with 1–2 real members
4. Add to i18n store
5. Cross-reference in the screen specification (D3.6)
