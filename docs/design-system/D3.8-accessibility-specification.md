## 1. Commitment

The Eagle Generation Portal targets **WCAG 2.2 Level AA** across every public and member-facing screen, and every admin console screen. This is non-negotiable per Charter §21.5.

Accessibility is verified at three layers:

| Layer | Tool | Frequency |
|-------|------|-----------|
| Development | Storybook a11y panel (axe-core) | Every story, live |
| CI | `@axe-core/playwright` | Every PR |
| Manual | Screen reader + keyboard audit | Before each release gate |

## 2. Rules applied across every component

### 2.1 Focus management

- Every interactive element uses `focus-visible:outline-none focus-visible:shadow-focus`
- `shadow-focus` from D3.1a provides the double-ring pattern — visible on light and dark surfaces
- Modal, Drawer, CommandPalette **trap focus** while open
- Sheet does **not** trap focus (it is inline, not modal)
- On close, focus returns to the element that triggered the dialog

### 2.2 Keyboard operation

| Action | Key |
|--------|-----|
| Activate button / link | `Enter` or `Space` |
| Toggle checkbox / radio / switch | `Space` |
| Navigate within radio group | Arrow keys |
| Open modal / drawer | `Enter` on trigger |
| Close modal / drawer / palette | `Esc` |
| Toggle command palette | `⌘K` / `Ctrl+K` |
| Move through command palette results | Up / Down arrows |

Every screen must be **fully navigable without a mouse**.

### 2.3 Colour and contrast

- Body text: 4.5:1 minimum (WCAG 2.2 AA normal text)
- Large text (18pt+ or 14pt+ bold): 3:1 minimum
- UI components and graphical objects: 3:1 against adjacent colours
- Colour is never the sole carrier of meaning — always pair with text, icon, or shape
- Verified pairs in `docs/design-system/D3.1a-design-tokens.md` §2.3

### 2.4 Semantic HTML

- Use native elements first: `<button>`, `<input>`, `<label>`, `<nav>`, `<main>`, `<header>`, `<aside>`
- `<div role="button">` is a defect — use `<button>`
- `<span onClick>` is a defect — use `<button>` or `<a>`
- Form labels use `<label htmlFor>` — enforced by the FormField wrapper

### 2.5 ARIA

- Use ARIA only when native semantics are insufficient
- `role="alert"` for urgent messages (form errors, danger alerts)
- `role="status"` for non-urgent state changes (info alerts, bulk selection count)
- `aria-busy="true"` on loading regions
- `aria-hidden="true"` on purely decorative SVGs and emojis
- `aria-label` required on icon-only buttons

### 2.6 Touch targets

- Minimum 44×44 px on touch surfaces (xs and sm breakpoints)
- Implemented via `min-h-11` on interactive components at mobile
- Admins on desktop can use smaller targets but should not fall below 32×32

### 2.7 Motion

- `prefers-reduced-motion: reduce` collapses all animation durations to 0ms
- Handled by `styles/tokens.css`
- Never rely on animation alone to convey state

## 3. Screen-reader contract

Every component documents its ARIA contract in D3.1b. Consolidated reference:

| Component | Role | Key ARIA |
|-----------|------|----------|
| Button | `button` | `aria-busy` when loading |
| Input | `textbox` | `aria-invalid`, `aria-describedby`, `aria-required` |
| FormField | — | Wires `aria-describedby` to hint/error/success IDs |
| Checkbox | `checkbox` | `aria-checked="true\|false\|mixed"` |
| RadioGroup | `radiogroup` | `aria-required`, arrow-key navigation |
| Switch | `switch` | `aria-checked="true\|false"` |
| Modal | `dialog` | `aria-modal="true"`, `aria-labelledby`, `aria-describedby` |
| ConfirmDialog | `alertdialog` | Initial focus on Cancel button |
| Drawer | `dialog` | `aria-modal="true"` |
| CommandPalette | `dialog` + `combobox` | `sr-only` title/description |
| Sheet | `complementary` | `aria-hidden` when closed |
| Toast | `status` or `alert` | Per variant |
| Pagination | `nav` | `aria-current="page"` on active page |
| BulkActionBar | `region` | `aria-live="polite"` on count |
| SearchInput | `searchbox` | `aria-label` required |

## 4. Critical journeys verified by axe-core

These journeys must pass automated accessibility scans before every release:

1. **Membership application** — `/apply`, `/apply/form`, `/apply/submitted`
2. **Login** — `/login` (once it exists)
3. **Onboarding** — `/onboarding`
4. **Member dashboard** — `/dashboard`
5. **Admin application review** — `/admin/applications`
6. **Admin application detail** — `/admin/applications/[id]`
7. **Admin decision** — `/admin/applications/[id]` decision panel

Each is scanned by Playwright with `@axe-core/playwright` on every PR.
