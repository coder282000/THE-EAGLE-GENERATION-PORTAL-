## 1. Breakpoints

Matches Charter §21.1. Design at xs first, then enhance.

| Name | Width | Devices |
|------|------:|---------|
| `xs` | <640px | Phones (design here first) |
| `sm` | >=640px | Large phones |
| `md` | >=768px | Tablets |
| `lg` | >=1024px | Laptops |
| `xl` | >=1280px | Desktop, admin console |

## 2. Global layout rules

### 2.1 Member portal (Layer 1 + Layer 2)

| Breakpoint | Navigation | Content |
|------------|-----------|---------|
| xs | **Bottom tab bar** (5 items, most important actions) | Single column, full-bleed cards |
| sm | Bottom tab bar | Single column, wider padding |
| md | Top bar + hamburger drawer | Two-column for cards where useful |
| lg | Sidebar + top bar | Two or three columns |
| xl | Sidebar + top bar | Max content width 1280px, centred |

### 2.2 Admin console (Layer 3)

| Breakpoint | Navigation | Content |
|------------|-----------|---------|
| xs | Hamburger drawer | Single column, cards replace tables |
| sm | Hamburger drawer | Single column |
| md | Hamburger drawer, persistent header | Two-column for KPIs |
| lg | Collapsible sidebar (icon-only when collapsed) | Tables enabled, three columns |
| xl | Expanded sidebar | Full layout, max content width 1440px |

## 3. Component-level behaviour

### 3.1 Tables

Rule from Charter §21.2: **Tables become cards below `md`. Never horizontally scroll a data table on a phone.**

| Breakpoint | Behaviour |
|------------|-----------|
| xs / sm | Column-priority sort. Each row renders as a stacked card with 3–4 key fields visible; remaining fields under a "Details" disclosure |
| md | Full table with horizontal scroll if column count exceeds viewport |
| lg+ | Full table, no scroll |

The DataTable component (D3.1b Part 3) implements this via `columns[].mobilePriority`.

### 3.2 Forms

| Breakpoint | Behaviour |
|------------|-----------|
| xs / sm | Single column, labels above fields, 16px input text (prevents iOS auto-zoom), numeric keypads for numeric fields |
| md+ | Same single column for readability. Horizontal labels only in admin settings forms |
| lg+ | Optional two-column layout for independent field groups |

### 3.3 Modals

| Breakpoint | Behaviour |
|------------|-----------|
| xs | Full-screen sheet from bottom (`Drawer side="bottom"`), 90vh max height |
| sm | Centred dialog with `size="md"` |
| md+ | Centred dialog, size chosen by caller |

The Modal component uses CSS to switch to bottom-sheet presentation at xs automatically.

### 3.4 Drawers

| Side | xs | sm+ |
|------|----|----|
| right / left | Full viewport width | Width per `size` prop (400 / 520 / 720) |
| bottom | Height per `size` (40vh / 60vh / 85vh) | Same |

### 3.5 Pagination

| Breakpoint | Behaviour |
|------------|-----------|
| xs | Prev / Next buttons + "1 of 8" text |
| sm+ | Full numbered pagination with first/last/prev/next |

### 3.6 FilterBar

| Breakpoint | Behaviour |
|------------|-----------|
| xs / sm | Search input inline + "Filters (n)" button opening a bottom Drawer |
| md | Filters inline as dropdowns |
| lg+ | Full row: search + filters + actions |

### 3.7 Command palette (⌘K)

| Breakpoint | Behaviour |
|------------|-----------|
| xs / sm | Full-screen overlay, input at top, results scroll |
| md+ | Centred dialog, 560px max width, opens 15vh from top |

### 3.8 Empty states

Same layout at all breakpoints. Icon + title + description + optional CTA. Centred vertically within the available container space.

## 4. Images and media

- All images use `next/image` with responsive `sizes` prop
- Format: WebP with AVIF fallback (handled by next/image)
- Lazy-load everything except above-the-fold hero images
- Video lessons: `preload="none"`, poster image, lazy-load player

## 5. Performance budget by breakpoint

Charter §21.4 budgets apply on **mid-range Android on 3G**, which is our worst-case:

| Metric | Target |
|--------|-------:|
| First Contentful Paint | <1.8s |
| Largest Contentful Paint | <2.5s |
| Time to Interactive | <3.5s |
| Cumulative Layout Shift | <0.1 |
| Initial JS bundle (gzipped) | <200KB |
| Lighthouse Performance | >=90 |

Current actuals from last Vercel build:
- First Load JS shared: 87.5 kB
- Largest route: 156 kB (community feed)
- Every route under 200 kB

Enforced in CI via Lighthouse CI.

## 6. Testing checklist

Before each release:

- [ ] Screens reviewed at 360px (xs), 768px (md), 1280px (xl)
- [ ] Tables collapse to cards below md
- [ ] Forms are single-column on mobile
- [ ] Modals present as bottom sheets on xs
- [ ] Bottom tab bar present on member portal at xs/sm
- [ ] Admin sidebar collapses at lg
- [ ] No horizontal scroll anywhere except tables at md+
- [ ] Touch targets >=44px on interactive elements at xs
- [ ] Images are lazy-loaded except above the fold
- [ ] Lighthouse budget passes
